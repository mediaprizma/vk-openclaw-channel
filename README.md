# VK-канал для OpenClaw

Интеграция ВКонтакте с [OpenClaw](https://github.com/openclaw/openclaw).

Этот проект подключает агента OpenClaw к сообществу ВКонтакте через VK Bots Long Poll API. Поддерживаются личные сообщения, групповые чаты, передача медиафайлов, клавиатуры, реакции, сообщения о процессе обработки и несколько VK-аккаунтов.

> Этот репозиторий является независимым проектом, который развивается и поддерживается **mediaprizma**.

## Shared master/operator chat

Set `masterVkId` to the VK user id of the human master. Each client keeps its own OpenClaw session. When an agent sends a clarification question to the master's VK DM, the plugin records the real VK outbound `message_id` together with the originating client session. The master can then use VK's native **Reply** action on that exact question.

The reply is authenticated by `masterVkId`, correlated by the replied-to VK `message_id`, injected into the original client session, and the agent's next response is delivered back to that client. Questions from multiple client sessions can coexist in the same master chat.

A master message without **Reply** to a known agent question is intentionally ignored because it has no unambiguous client session.

## Требования

- OpenClaw **2026.9.x или новее**
- Версия Node.js, поддерживаемая установленной версией OpenClaw
- Сообщество ВКонтакте с токеном сообщества
- Включённый VK Bots Long Poll API

## Возможности

- Личные сообщения ВКонтакте
- Групповые беседы ВКонтакте
- Единая клиентская сессия для сообщений и публичных комментариев одного VK-пользователя
- Однократный импорт до 30 последних сообщений предыдущей VK-переписки при создании новой клиентской сессии
- Отдельный маршрут ответа для каждого входящего события: ЛС, комментарий к записи или комментарий к Клипу
- Несколько сообществ ВКонтакте
- Политики доступа для личных и групповых сообщений
- Отдельные системные промпты для разных диалогов
- Форматирование сообщений в стиле Markdown
- Изображения, документы и аудио
- Клавиатуры ВКонтакте и callback-события
- Реакции на сообщения
- Индикатор набора текста
- Редактирование и удаление сообщений
- Статусные сообщения о ходе обработки
- Ссылки OpenClaw SecretRef для хранения токенов VK
- Комментарии к записям и VK Кли́пам с сохранением исходного поста/клипа
- Передача агенту текста, ссылки и доступных изображений исходной публикации
- Продолжение того же клиентского контекста при переходе из комментария в личные сообщения
- Защита от ответа собственного комментария как нового входящего события

Канал использует существующий runtime каналов OpenClaw и не создаёт отдельную систему агентов или обработки сообщений.

## Настройка сообщества ВКонтакте

В настройках сообщества ВКонтакте:

1. Откройте **Управление сообществом → Сообщения** и включите сообщения сообщества.
2. Откройте **Работа с API → Ключи доступа** и создайте токен сообщества.
3. Выдайте разрешения, необходимые для используемых функций:
   - **Сообщения**
   - **Управление сообществом**
   - **Фотографии** — для отправки изображений
   - **Документы** — для файлов и голосовых сообщений
4. Откройте **Работа с API → Long Poll API** и включите его.
5. Включите необходимые типы событий для вашей конфигурации OpenClaw.
6. Если бот будет использоваться в групповых беседах, разрешите добавление сообщества в беседы.

Храните токен сообщества в секрете. Не добавляйте его в этот репозиторий.

## Установка

Для опубликованного npm-пакета:

```bash
openclaw plugins install vk-openclaw-channel --force --accept-capabilities
```

Для локальной разработки:

```bash
git clone https://github.com/mediaprizma/vk-openclaw-channel.git
cd vk-openclaw-channel
npm install
npm run build
openclaw plugins install --link ./dist/index.js
```

После установки проверьте плагин:

```bash
openclaw plugins info vk-openclaw-channel --json
openclaw channels status --json --probe
```

После изменения конфигурации при необходимости перезапустите Gateway:

```bash
openclaw gateway restart
```

## Настройка через Control UI

В **Settings → Channels → VK (ВКонтакте)** основные параметры разделены по смыслу:

- **Токен сообщества VK** — токен сообщества. Лучше хранить через SecretRef.
- **VK ID мастера** — личный VK ID мастера, которому агент может задавать уточняющие вопросы.
- **Инструкция для агента** — общие правила ответа в VK.
- **Комментарии VK** — включение комментариев и отдельные переключатели для записей, Кли́пов и видео.
- **Сообщества VK** — дополнительные аккаунты, если подключено несколько сообществ.
- **Отдельные беседы** и технические параметры находятся в расширенных настройках.

Поля, которые обычно не требуется менять вручную, относятся к расширенным настройкам. Для большинства установок достаточно указать токен, VK ID мастера, политику доступа и нужные типы комментариев.

## Конфигурация

Добавьте VK-канал в `~/.openclaw/openclaw.json`:

```json
{
  "channels": {
    "vk-openclaw-channel": {
      "enabled": true,
      "token": "<VK_COMMUNITY_TOKEN>",
      "dmPolicy": "pairing"
    }
  }
}
```

### Комментарии

Комментарии обрабатываются как обращения того же VK-пользователя, что и личные сообщения, поэтому у клиента сохраняется единый контекст. Маршрут ответа хранится отдельно: комментарий получает ответ в комментарии, а последующее личное сообщение — в ЛС.

Для комментария к записи плагин сохраняет owner_id + post_id и ссылку на исходную запись. Текст самой записи через VK API не запрашивается: агент при необходимости открывает ссылку в браузере и анализирует доступный контент. Для Клипов и видео плагин получает доступные метаданные и превью через соответствующий VK API.

Если для расчёта нужны персональные детали, агент может попросить клиента продолжить разговор в личных сообщениях. При переходе в ЛС origin комментария сохраняется в клиентской сессии. Если у клиента несколько недавних обращений к разным публикациям и источник неоднозначен, агент не должен угадывать — он может попросить ссылку на нужный пост.

Пример:

```json
{
  "channels": {
    "vk-openclaw-channel": {
      "comments": {
        "enabled": true,
        "postComments": true,
        "clipComments": true,
        "videoComments": false
      }
    }
  }
}
```

Для VK Bots Long Poll должны быть включены события wall_reply_new и video_comment_new. Комментарии к Клипам приходят через video-comment event; плагин определяет Клип по типу видео short_video.

### Политики доступа

Для личных сообщений доступны:

- `pairing`
- `allowlist`
- `open`
- `disabled`

Пример:

```json
{
  "channels": {
    "vk-openclaw-channel": {
      "enabled": true,
      "token": "<VK_COMMUNITY_TOKEN>",
      "dmPolicy": "allowlist",
      "allowFrom": [123456789]
    }
  }
}
```

Для групповых бесед используются `groupPolicy` и `groupAllowFrom`.

### Настройки отдельных бесед

Для отдельных групповых бесед можно задать собственные параметры:

```json
{
  "channels": {
    "vk-openclaw-channel": {
      "groups": {
        "2000000123": {
          "enabled": true,
          "allowFrom": [123456789],
          "requireMention": true,
          "systemPrompt": "Отвечай кратко и по существу."
        }
      }
    }
  }
}
```

### Несколько сообществ ВКонтакте

Можно настроить несколько токенов сообществ как отдельные аккаунты:

```json
{
  "channels": {
    "vk-openclaw-channel": {
      "accounts": {
        "sales": {
          "enabled": true,
          "token": "<SALES_TOKEN>",
          "dmPolicy": "allowlist",
          "allowFrom": ["*"]
        },
        "support": {
          "enabled": true,
          "tokenFile": "/etc/openclaw/vk-support.token",
          "dmPolicy": "pairing"
        }
      }
    }
  }
}
```

## Безопасность токена

Токен можно передать через:

- `token`
- `tokenFile`
- `VK_TOKEN`
- OpenClaw SecretRef

Пример SecretRef:

```json
{
  "channels": {
    "vk-openclaw-channel": {
      "token": {
        "source": "env",
        "provider": "default",
        "id": "VK_TOKEN"
      }
    }
  }
}
```

Для production-установок рекомендуется использовать провайдер секретов или защищённый файл с токеном вместо хранения учётных данных непосредственно в конфигурации OpenClaw.

## Медиафайлы

Канал поддерживает отправку:

- изображений;
- документов;
- аудио;
- голосовых сообщений.

Для этих операций токену сообщества нужны соответствующие разрешения на работу с `photos` и `docs`.

Если VK не может напрямую скачать изображение по URL, канал может скачать файл через хост OpenClaw и затем загрузить его в VK.

## Форматирование

Ответы OpenClaw могут использовать Markdown-подобное форматирование, поддерживаемое VK через `format_data`:

- **жирный текст**
- *курсив*
- ***жирный курсив***
- [ссылки](https://example.com)

Неподдерживаемый Markdown отправляется как обычный текст.

## Разработка

Установите зависимости:

```bash
npm install
```

Сборка:

```bash
npm run build
```

Запуск тестов:

```bash
npm test
```

Перед публикацией изменений рекомендуется выполнять проверку типов и предусмотренные проектом проверки.

При первом входящем сообщении клиента, для которого ещё нет OpenClaw-сессии, канал один раз запрашивает `messages.getHistory` по VK ID клиента. Импортируется ограниченное окно до 30 сообщений, затем оно добавляется перед текущим сообщением как контекст предыдущей переписки. Если сессия уже существует, VK API для истории повторно не вызывается. Имена пользователей обогащаются через `users.get`; при недоступности имени используется VK ID. Ошибка импорта истории не блокирует обработку текущего сообщения.

## Диагностика

Проверить состояние канала:

```bash
openclaw channels status --json --probe
```

Проверить информацию о плагине:

```bash
openclaw plugins info vk-openclaw-channel --json
```

Если канал настроен, но не запускается, проверьте логи Gateway OpenClaw и убедитесь, что:

1. токен VK действителен;
2. Bots Long Poll API включён;
3. необходимые события VK включены;
4. плагин включён;
5. настроенная политика доступа разрешает сообщения от отправителя;
6. после соответствующих изменений конфигурации был перезапущен Gateway.

При ошибках, связанных с доступом к медиафайлам, создайте токен сообщества заново с необходимыми разрешениями VK и перезапустите Gateway OpenClaw.

## Текущая архитектура комментариев

Входящие обращения нормализуются по каноническому VK user id. Поэтому один клиент использует единый контекст OpenClaw независимо от того, написал он в личные сообщения, под записью или под Клипом.

Маршрут доставки хранится отдельно от клиентской сессии:

- обычное сообщение → личные сообщения;
- комментарий к записи → комментарий к той же записи;
- комментарий к Клипу → комментарий к тому же видео/Клипу.

Исходный контент и его медиа являются частью контекста текущего обращения. Переход из публичного комментария в ЛС не теряет origin.

Следующий этап развития — расширение тестового покрытия, дедупликация и дополнительные правила модерации/лимитов для публичных комментариев.
